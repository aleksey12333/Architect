# AI Architect Studio — Universal BIM/CAD Constitution (CLAUDE.md)

## 1. Системные правила для Claude Code
- **Язык общения:** Все объяснения, отчеты и ответы пользователю пиши **строго на русском языке**. Имена классов, методов и переменных в коде — на английском.
- **Экономия лимитов:** Запускай сборку ТОЛЬКО в тихом режиме: `dotnet build --nologo -v q`.
- **Защита моделей:** В папке `LocalModels/` УЖЕ скачаны и лежат готовые `.gguf` файлы. Никогда не удаляй их, не перезаписывай и не читай их содержимое и не заходи в папку через терминал. В `.csproj` обязательно исключи `LocalModels/**` из копирования при сборке (`CopyToOutputDirectory = Never`).
  - Точные имена файлов (приложение в рантайме обращается к ним по пути `C:\AIArchitectStudio\LocalModels\`): `qwen2.5-coder-3b-instruct-q4_k_m.gguf`, `qwen2.5-coder-7b-instruct-q4_k_m.gguf` (константы `AiModelCatalog.Qwen3BFile` / `Qwen7BFile`).

### 1.1 Закреплённые технические решения
- **Локальный ИИ — сервер Ollama (Zero-Config):** `OllamaProcessManager` при старте пингует `/api/tags` (адрес из `AppSettings.OllamaEndpoint`, «localhost» → 127.0.0.1 — на Windows отказ ::1 стоит ~2 с), иначе ищет `ollama.exe` (PATH, `%LOCALAPPDATA%\Programs\Ollama`, `%ProgramFiles%\Ollama`) и скрыто запускает `ollama serve` (`CreateNoWindow`, `UseShellExecute=false`, `OLLAMA_MODELS` — из настроек или переменной пользователя; у пользователя модели в `D:\models`), ждёт готовности 30 с, публикует модели в `AiModelRegistry.SetOllamaModels` (ключ `ollama:<имя>`, `ParameterBillions`, `SizeGb`, `Capabilities`). Запущенный приложением сервер останавливается при выходе (и в `AIA_DEBUG_EXIT`): `Kill(entireProcessTree)` с ожиданием до 3 с; кроме того, сразу после старта `ollama serve` входит в объект задания Windows `ChildProcessJob` (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) — при аварийном завершении или снятии приложения из диспетчера задач система сама завершает сервер и раннеры моделей (сирот не остаётся; не удалять). Фоновый запуск отменяется при выходе (`_lifetime`), отмена запроса одного вызывающего не отменяет общий запуск (`WaitAsync`); адрес из настроек — `NormalizeEndpoint` (без схемы → http://, мусор/не http(s) → адрес по умолчанию, без `UriFormatException`). Статус — пилюля над доком («Подключение локального интеллекта…» / «Запуск локального интеллекта…» → «Локальный интеллект готов · модулей N») и строка в «Составе КБ». `OllamaAIProvider` — потоковый `/api/chat` (NDJSON, `Progress`), `think` для рассуждающих моделей (`gpt-oss` — "medium"), иначе `format: "json"`; `num_ctx` по размеру промпта (8–32 К). При первой готовности движка встроенный Qwen в доке заменяется моделью Ollama (`PreferOllamaModel`).
- **Встроенный резерв:** `LLamaSharp.Backend.Vulkan.Windows` с откатом на `LLamaSharp.Backend.Cpu` остаётся только как офлайн-резерв без сервера (меню «Встроенные (LLamaSharp, резерв без сервера)»); в автоподбор ролей Совета при наличии моделей Ollama не идёт (OOM при нескольких моделях в процессе). `DirectML` не ищем и не используем.
- **Рассуждения `<think>`:** `ReasoningText.Separate` отделяет блоки `<think>/<thinking>/<reasoning>` (несколько, незакрытый хвост, шаблон deepseek-r1 без открывающего тега) от ответа; `AiResponse.Reasoning`, `AiJsonExtractor.TryExtract` и `AgentPrompts.TryReadObject` разбирают только ответ. В ленте «Коллоквиум КБ · Live Debate» рассуждения — мелкий полупрозрачный курсив «Внутренние рассуждения агента» (свёрнуто — хвост ~420 символов, живой поток).
- **C# / MVVM:** в `.csproj` всегда `<LangVersion>preview</LangVersion>` — нужно для `CommunityToolkit.Mvvm 8.4.2` и partial-свойств `[ObservableProperty] public partial ...`.
- **Секреты:** API-ключи всех облачных провайдеров (Gemini, OpenAI, Claude, OpenRouter) хранятся только в диспетчере учётных данных Windows (`SecretStore` → `Windows.Security.Credentials.PasswordVault`, ресурс `AIArchitectStudio`, имя записи — `SecretStore.KeyNameFor(provider)`). В `settings.json` ключей нет; открытый `GeminiApiKey` из старых версий автоматически мигрирует в PasswordVault при запуске (`SettingsService.MigrateLegacyApiKey`).
- **Демо-сцены (шаблоны):** `PresetScenesService` — четыре детальных пресета (`cottage`, `frame` — каркасный корпус 24 × 18 м, 4 этажа, с явными осями `DemoScene.Axes`, `tower`, `pavilion`; `PresetInfo`: подпись, полное название RU/EN, глиф). Кнопок пресетов в главном окне нет — шаблоны только в стартовом окне (плитки с превью `Assets\Templates\<id>.png` — «Белый макет» с прозрачным фоном, рендер `AIA_DEBUG_PRESET=<id>;CLAY=1;AXES=0;RENDER4K=путь;alpha`). Все пресеты создаются только через `PresetScenesService` (устаревший `DemoSceneFactory` удалён).
- **Запуск (стартовая оболочка, `App.OnLaunched`):** первый запуск (нет `settings.json`) или `FollowSystemTheme` → тема Cupertino Light/Dark по `AppsUseLightTheme` (`SystemThemeDetector`); `Views/SplashWindow` (640 × 400, знак `Views/AppLogo` (строгий векторный чертёж здания с осями и размерной линией, без «искры») проявляется и вырастает 0.9 → 1.0 за 0.8 с, заголовок «Architect Studio Pro», статусы «Запуск вычислительного ядра… / Инициализация 3D-ядра… / Проверка модулей…»; в это время стартуют Ollama и проверка ключей, в UI-потоке создаются `StructuralAnalysisService` и `MainViewModel`) → `Views/WelcomeWindow` (960 × 620: «Новый проект», «Открыть…», «Настройки», недавние `.aia` — `AppSettings.RecentProjects`, шаблоны 2 × 2, онбординг-мастер из двух шагов) → главное окно с выбранной сценой (`StartupChoice`, `MainViewModel.LoadStartupScene/StartEmptyProject`, проявление островов `MainWindow.PrepareEntranceAnimation`). Окна без системной рамки — `WindowChrome.ConfigureBorderless` (`SetBorderAndTitleBar(true, false)`: скругление 8 px и тень DWM, `DesktopAcrylicBackdrop`); в WinUI 3 нет WPF `WindowStyle/AllowsTransparency`. Закрытое без выбора стартовое окно завершает приложение (`ShutdownServices`). Без оболочки (`AppStartupOptions.StartupPresetId` = `cottage`) — сразу главное окно с Пресетом 1: так запускается **любой** сценарий с переменной `AIA_DEBUG_*`, кроме переменных самой оболочки (`FIRSTRUN`, `ONBOARDING`, `SPLASHHOLD`, `WELCOMEPICK`, `LANG`, `PROFILE`, `SHELL`) — автотест и съёмка не ждут заставку. `ShowWelcomeScreen = false` — после заставки сразу пустой проект.
- **Уровень опыта (`UserExperienceProfile`, `AppSettings.ExperienceProfile`, онбординг «Укажите ваш опыт в проектировании», `OnboardingCompleted`):** `Beginner` («Студент / Практикант», базовый интерфейс) — чат, инспектор, смета, рулетка, макет, прогулка (скрыты оси и их вкладка, каркас, Section Box, OSnap); `Architect` («Архитектор», стандартный) — плюс оси, каркас, Section Box, OSnap, солнце и тени; `StructuralEngineer` («Инженер-конструктор (ГИП)», продвинутый) — весь интерфейс (прогноз K_исп вариантов Совета). Видимость — `MainViewModel.IsArchitectUi / IsEngineerUi`, ширина сегментов вкладок — `XamlHelpers.StarIf`, шаблоны данных — `XamlHelpers.CurrentProfile/VisEngineer`; короткие подписи сегмента настроек — ключи `Profile*Short`. Скрытие профилем выключает соответствующие режимы, но не блокирует свойства VM (автотест ставит `IsAxesTab` при любом профиле).
- **Модули и Плагины (`WorkspaceModules`, `AppSettings.Modules`, null → `EffectiveModules` = набор уровня):** независимые от уровня тумблеры «Расчёт инсоляции по СанПиН» (блок СанПиН панели «Инсоляция и Тени»; кнопка солнца — `IsSolarUi` = архитектор или модуль), «КЭ-анализ и карта напряжений» (карта напряжений, усилия в инспекторе, нагрузки и результаты вкладки «Анализ»), «Визуализация 3D-армирования (КЖ)» (кнопка «Армирование»), «Инспектор коллизий каркаса» (раздел вкладки «Анализ»; вкладка видна при `IsAnalysisTabUi`), «Ведомость объёмов и сталей» (кнопка в верхнем баре и на вкладке «Смета»). `WorkspaceModules.ForProfile`: студент — ни одного, архитектор — инсоляция и ведомость, ГИП — все. Онбординг — мастер `WelcomeWindow`: шаг 1 «Укажите ваш опыт в проектировании» (клик по карточке сразу ведёт дальше), шаг 2 «Выберите необходимые модули для работы» — 5 карточек-чекбоксов (`WelcomeWindow.Modules`, галочки по `ForProfile`, множественный выбор, «Как рекомендовано», «Назад», «Начать работу»); выбранный набор сохраняется в `AppSettings.Modules` и передаётся в `MainViewModel.SelectProfile(profile, modules)`. `AIA_DEBUG_PROFILE` ставит набор уровня; в настройках смена уровня подставляет его набор, «По уровню опыта» — сброс. Выключенный модуль гасит свои режимы (`OnModulesChanged`).
- **Подписи чата:** «Вы / Система / Ошибка / Проектировщик» берутся из `LocalizationService` (`ChatRoleUser`, `ChatRoleSystem`, `ChatRoleError`, `ChatRoleAssistant`, статический `LocalizationService.Lookup`); `ChatMessageModel.Language` (не сериализуется) переключается у всей истории при смене RU/EN, `Header` привязан `Mode=OneWay`.
- **HelixToolkit.WinUI 2.27.3 в unpackaged-режиме:** тема библиотеки (`Generic.xbf` из `HelixToolkit.WinUI.pri`) содержит служебные экземпляры `Element3D`, создание которых при загрузке темы роняет WinUI нативно (`0xC000027B`, `0x80004005`) прямо в момент добавления `Viewport3DX` в дерево. Решение: таргет `ExcludeHelixLibraryPri` в `.csproj` исключает библиотечный `.pri`, а собственная тема `HelixToolkit.WinUI/Themes/Generic.xaml` (тот же URI, только стили и шаблон `Viewport3DX`) подставляется вместо неё. Не удаляй ни то, ни другое.
- **Выход приложения:** рендер-хост Helix (`DefaultRenderHost`) запускает **не фоновый** поток `AsyncActionThread` и останавливает его только в `EndD3D`/`Dispose`; без этого процесс остаётся в памяти после закрытия окна. Поэтому `MainWindow.Closed` вызывает `Viewport.Shutdown()` (отписка, `RenderHost.EndD3D()` + `Dispose()`, `DefaultEffectsManager.Dispose()`) и `WebBridgePanel.Shutdown()` (отписка от статического `Clipboard.ContentChanged`, `WebView2.Close()`); `LocalAIProvider.Dispose` не освобождает веса под идущей генерацией. Не удалять.
- **Gizmo-перетаскивание:** Helix не присылает `OnMouse3DMove` при зажатой кнопке, поэтому движение ведётся сырыми `PointerMoved/PointerReleased` (`AddHandler(..., handledEventsToo: true)`) с `CapturePointer`. Хит-тест Gizmo — по всем попаданиям луча (`FindHits`), т.к. стрелка может проходить внутри стены.
- **Визуальная самопроверка:** после изменений UI собирать, запускать и снимать скриншот (`CopyFromScreen`; скрипт съёмки должен вызывать `SetProcessDPIAware`, иначе кадр обрезается масштабированием), смотреть его глазами. - **Проёмы-пустоты:** `wall_opening` (хост — стена, `IsHostedType`) и `slab_opening` (хост — плита, плоская кровля, фундамент, терраса: `CanHostSlabOpenings`). Delete у окна/двери превращает их в `wall_opening` (`SceneStateService.DeleteElement`), Delete/«Замуровать» у пустоты удаляет её. Отверстия плит вырезаются трапецеидальным разбиением с правилом ненулевой обмотки (`MeshAccumulator.FillTrapezoids`, внешний контур — против часовой, отверстия — по часовой). В OBJ/DXF пустоты как тела не экспортируются (DXF — контуры на слое `OPENINGS`).
- **Координационные оси:** явные оси построек (`SceneStateService.GridAxes`, `StructuralGridAxis`, сохраняются в `.aia` v3 и в Undo) приходят с чертежа (`blueprint.gridAxes`) или из вкладки «Оси»; без них — автоматические по несущим (`StructuralAxesBuilder.AutoAxes`). Сетка строится по каждой постройке на отметке каждого этажа (`LevelElevations`), активный этаж фильтра — ярче; на плане — только активный этаж, на фасаде — линии уровней с отметками. Реентерабельность: список построек в редакторе осей обновлять инкрементально, без `Clear()` (иначе TwoWay-привязка ComboBox роняет приложение).
- **Транзакция Undo:** `SceneStateService.BeginUndoTransaction()` (using) открывает шаг один раз, все `PushUndo` внутри поглощаются — пакет любых правок (автоисправления коллизий, `SetTransform`, `AddElement`) = ровно один шаг Undo; `Discard()` убирает шаг, если ничего не изменилось. Совет КБ выпускает решения через `LoadScene(…, recordUndo: true)` из песочницы — тоже один шаг.
- **Транзакции и журнал изменений (фаза 7, `Models/Transactions/`):** шаг Undo — `BimTransaction` (имя + список `IElementChange`), а не клон сцены: `ParameterChange` (элемент, `ParameterSlotKind` + номер слота, «было/стало» `SlotValue` — массивы векторов по ссылке, как в слоте), `TypeChange` (старый/новый `BimElementType`, `OldTypeId/NewTypeId`), `LevelChange` (этаж + слоты LevelId/LevelIndex), `ElementFieldChange` (Id, Polygon2D, список Layers, копия словаря пользовательских параметров), `LayerContentChange` (правка пирога на месте — `MaterialLayers.AbsorbThickness` вызывает `BeginLayersEdit`), `ElementAdded`/`ElementDeleted` (позиция в списке), `ElementsCleared`, приватный `DocumentStateChange` (постройки/оси/размеры: снимок при открытии шага сравнивается при закрытии, значения возвращаются в те же объекты). Повторы одной ячейки (элемент + слот) в шаге сливаются (перетаскивание Gizmo — одна запись). `TransactionManager(ITransactionDocument, MaxHistory = 1000)`: элемент документа знает журнал (`ArchitecturalElement.Journal`, ставится в `Elements.CollectionChanged` после `Bind` этажа, снимается при удалении); сеттеры фасада и `Retype`/`SetLevelState` пишут только при `IsRecording` (открыт шаг и не идёт Undo/Redo) — вне документа (солвер, ИИ, клоны расчёта/экспорта, песочница без шага) запись стоит одну проверку. Undo/Redo пишут значения напрямую (`ApplySlot/ApplyType/ApplyLevel/ApplyField/ApplyLayerContent`) с прежними `PropertyChanged`, к тем же объектам (без клонов); во время применения `PushUndo` не открывает шаг (поле оси в редакторе поднимает `PropertyChanging`). Семантика прежних снимков сохранена: шаг пишет всё до следующего `PushUndo`/`BeginUndoTransaction`/Undo/`ClearHistory`; выделение «до/после» — с шагом; этажи `BimLevelTable` в журнал не входят (как и раньше — клоны делили этаж). Очистка списка — только `ClearElements()` (событие Reset старых элементов не сообщает).
- **`DocumentChanged(added, modified, deleted)` (`DocumentChangedEventArgs`: `Reason` Edit/Undo/Redo/Reset/Filter, `IsReset`, `IsStructural`):** операции `SceneStateService` сообщают затронутые элементы через `Changed(...)`; внутри явной транзакции изменения копятся и уходят одним событием при закрытии (Commit); Undo/Redo — по составу документа до и после шага; изменение построек — `IsReset`. Вьюпорт подписан только на `DocumentChanged`: удалённые убирает, добавленные и изменённые (с хостами) перестраивает поштучно, полная перестройка — при `IsReset` (новая сцена, фильтр этажа, постройки), непривязанном `slab_opening` или пакете > max(64, ½ сцены). `StructuralAnalysisService` и проверка пересечений — тоже на `DocumentChanged`. `SceneChanged` (структурные изменения, Undo/Redo, загрузка) и `ElementsTransformed` (= Modified) выводятся из того же события для списков интерфейса и инспектора `MainViewModel`.
- **ИИ без изменения сцены:** `AIOrchestrator.Solve(text, ctx, target)` разбирает ответ и прогоняет солвер без мутации, `AIOrchestrator.Commit(solved, target)` применяет к любой сцене (живой или песочнице `DesignFixEngine.Sandbox`); `ApplyResponseText` = Solve + Commit. JSON ИИ понимает пироги: `"layers": "floor|flat_roof|foundation|exterior_wall"` или массив `{name, thickness (мм), role, density}` (`ParametricSolverService.ApplyLayers`).
- **Камера «Показать всё»:** перспектива вписывается точно по проекциям 8 углов габарита на оси камеры (а не по габаритной сфере), с учётом «безопасной зоны» между островами. `ZoomExtentsRequested` обрабатывается через `DispatcherQueue.TryEnqueue` — после отложенной перестройки геометрии, иначе новая постройка («+ К участку», ответ ИИ) не попадает в кадр.

## 3. Технические стандарты 3D, Координат и Производительности
1. **Защита от краша `0xc000027b`:** Инициализируй `Viewport3DX`, `DefaultEffectsManager`, камеры и свет строго программно в code-behind по событию `Loaded`.
2. **Система координат Y-Up:** Земля — плоскость `XZ` при `Y = 0`. Высота растет вверх по оси `Y`. Центр элемента высотой `H`, стоящего на плите/земле с отметкой `BaseY`, всегда равен `BaseY + H / 2`.
3. **Масштабируемость (От бани до уникального небоскреба):**
   - Используй процедурное размножение этажей и конструкций в C# (`ParametricSolverService`): ИИ задает высокоуровневые параметры (`RepeatLevels`, `TwistAnglePerFloor`, `TaperScalePerFloor`, `Polygon2D`), а C#-солвер за 1 мс разворачивает их в точные 3D-узлы без перегрузки памяти.
4. **Привязка диалогов:** Все `FileOpenPicker` и `FileSavePicker` инициализируй через `WindowNative.GetWindowHandle`.

## 5. ИИ-архитектура (`Services/AI`)
Конвейер: модель → JSON сцены (`AiSceneDocument`) → C#-солвер → сцена (один шаг Undo) → отчёт солвера в чате и `ErrorInfoBar` → автоподгонка камеры (кроме режима Modify). Оркестратор — `AIOrchestrator`; скрытое ТЗ для всех моделей — `SystemPrompts`.
1. **Смарт-анализатор ключей (`AiKeyInspectorService`):** провайдер определяется по префиксу (`AIza…` Gemini, `sk-ant-…` Claude, `sk-or-…` OpenRouter, `sk-…` OpenAI); реальный HTTP-запрос проверяет ключ и загружает актуальный список моделей в `AiModelRegistry` (кэш списка — в `settings.json`, сам ключ — в PasswordVault). 2. **Облачные провайдеры:** `GeminiAIProvider`, `OpenAiCompatibleProvider` (OpenAI / OpenRouter), `ClaudeAIProvider` (серия Claude 5.5: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`). Vision-режимы передают изображение после `ImagePreparer`.

4. **Чертежи и PDF (адаптивный конвейер):** любой `.pdf` открывает `PdfPagePickerDialog` — миниатюры всех страниц, «Автовыбор листов с чертежами» (`PdfBlueprintExtractor.AnalyzeAsync/AutoSelect`: пропуск обложек, пустых и разреженных листов), ручные галочки, тип материала (`BlueprintKind`: авто / КЖ-КМ / АР-БТИ / эскиз-фото) и комментарий. Выбранные листы (до 12) рендерятся в JPEG ровно 2000 px (PdfPage растеризует в DIP — размер приводится вручную) и уходят модели как несколько изображений `AiImage` с подписью листа; для веб-чата собирается сводный лист. Промпт собирает `AdaptivePromptBuilder` (правила точности «ничего не придумывать» + правила типа материала + схема `blueprint`). Ответ с блоком `blueprint` (оси, уровни, сечения, расстановки колонн/балок/стен, плиты, отверстия, кровля, фундамент) разворачивает `BlueprintCompilerService` в элементы с закреплёнными отметками (`AiElementSpec.Pinned` — гравитация солвера их не двигает). Ссылки на оси: `["2","Б"]` (марка цифровой оси — тоже строка), `["2","Б",dx,dy]`, «2/Б», диапазоны «1-6/А-Г»; координаты `[x, y]` — как на листе (y вверх = −Z сцены).
   - **Векторный слой PDF (`Services/Pdf/PdfNativeContentExtractor` + `PdfObjectReader` + `PdfFontDecoder`):** собственный разбор без библиотек — объекты сканированием «n g obj» (битые/инкрементальные xref), `/ObjStm`, фильтры Flate/LZW/ASCIIHex/ASCII85/RunLength с предикторами, дерево страниц с наследованием и `/Rotate`, Form XObject, BI…EI. Текстовые операторы BT/ET, Tf, Td/TD/Tm/T*, Tj/TJ/'/" с матрицами CTM×Tm, шрифты Type0 (Identity-H, встроенные CMap, /W), простые (WinAnsi/MacRoman, /Differences с AGL-кириллицей afii100xx), `/ToUnicode`, обратный cmap встроенного TrueType; CP1251 без ToUnicode — по сериям байтов ≥ 0xC0. Глифы склеиваются в строки (`MergeRuns`), векторы m/l/re/h — отрезки, 4+ кривых с квадратным габаритом — окружности (кружки марок осей). Скан без текста — пустой список без ошибок.
   - **Семантика (`BlueprintAnnotationAnalyzer` → `ExtractedBlueprintAnnotations`):** размерные числа 100..60000 кратные 5 (и «5х6000=30000») над параллельной размерной линией, цепочки по базовой линии (горизонтальные — X, повёрнутые — Z), оценка цепочки: совпадение суммы с общим размером (+10), числа посередине между кружками осей (+3 за каждое); отметки `[+-±]d,ddd`; марки осей в кружках (без кружков — повтор на другом конце оси); сечения из указаний («колонны К1 400х400», «толщиной 220 мм», h=/t=/Ø, труба, двутавр) и строк спецификаций (марка К/Б/П/С/Ф + сечение в той же строке), бетон B.., арматура А500С. `ToPromptBlock()` — блок «ТОЧНЫЕ ДАННЫЕ, ИЗВЛЕЧЕННЫЕ ИЗ ВЕКТОРНОГО СЛОЯ PDF» в `AdaptivePromptBuilder.DescribeSheets` (все провайдеры, локальный и веб-мост).
   - **Верификация перед 3D:** правая панель диалога (372 px) — шаги X/Z (мм, «5x6000» допустимо), отметки (м; N отметок = N−1 этажей, последняя — верх покрытия), колонны (профиль, W × D), балки (0 — нет), плита, стены, фундамент, кровля (плоская / с парапетом t × H / двускатная / вальмовая). Таблица следует за выбором листов, пока её не правили; «Из PDF» — перечитать. Кнопки: «Построить 3D через ИИ + Верификация» (листы + факты + `BlueprintDefinition.ToPromptBlock`, неподтверждённые типовые значения помечены) и «Прямая компиляция 3D по параметрам (Без ИИ, за 1 мс)» (`BlueprintDefinition.ToSceneJson` → `AIOrchestrator.ApplyResponseText` → компилятор → солвер, один шаг Undo, ~4 мс). Компилятор понимает `"roof": {"type":"flat","parapet":{"height","thickness"}}` и `contourOffset`.
5. **Локальный ИИ:** основной путь — сервер Ollama (`OllamaProcessManager` + `OllamaAIProvider`, см. 1.1); модели пользователя выбираются в доке (раздел «Ollama · локальный сервер») и в списках ролей Совета. Генерация ограничена **GBNF-грамматикой** (`Grammar(JsonGrammar, "root")`): только валидный компактный JSON, остановка сразу после закрытия корневого объекта. Температура запроса выше 0.1 (роли Совета) передаётся в сэмплер, иначе — 0.05.
6. **Мультиагентное конструкторское бюро (`Services/AI/Council`, режим дока «Совет КБ»):** роли `AiAgentRole` — `ChiefArchitect` (ГИП: посадка, оси, отметки, объёмы, остекление, кровля; t = 0.35), `StructuralEngineer` (каркас, плиты с проёмами, пироги; получает JSON ГИПа; t = 0.1), `NormsAndSafetyVerifier` (конвейер C#-проверщиков + критика модели; t = 0), `MasterSynthesizer` (выбор варианта; t = 0.2); подписи, глифы и цвета — `AgentRoles`. Маршрутизация `AgentModelRouter.Resolve(CouncilSettings, доступные модели, модель дока)`: явная привязка роли побеждает (недоступная → откат на автоподбор с пометкой), автоподбор ранжирует по профилю роли (Архитектор — Gemini, Конструктор — Claude, Нормоконтроль — ChatGPT/Qwen, Координатор — Claude/Gemini) со штрафом за повтор провайдера; один провайдер — все роли последовательно со своими промптами и температурами. Веб-аккаунт участвует в автоподборе, только если он выбран в доке. Шлюз `AgentModelGateway` (провайдеры через `AIOrchestrator.ProviderFor`, веб — `WebAccountBridgeProvider.AskAsync` с критерием приёма; модели без зрения получают задачу без изображений); `IAgentModelGateway` подменяется в автотесте. Модели Ollama ранжируются отдельно (`OllamaScore`: логарифм размера, зрение — Архитектору, coder — Конструктору, рассуждающие deepseek-r1/gpt-oss — Нормоконтролю и Координатору, веса > 75 % ОЗУ — штраф), семейства Ollama — разные «провайдеры» (`ProviderKey`). `AgentSwarmOrchestrator`: проектирование (Архитектор → Конструктор → **цикл самоисправления «ИИ ↔ C#»**: солвер на песочнице, конвейер проверщиков, реплика Аудитора с `recipes`; при критичных/коллизиях/K_исп > 1 Конструктор получает `AgentPrompts.Rework` — текущий JSON, `DefectList` (коды, элементы с координатами, причины, варианты) и рецепт — до `CouncilSettings.MaxReworkIterations` = 3 раундов, выпускается лучший раунд (`DesignIteration.Rank`) → варианты → позиции Конструктора и Архитектора → Координатор: в режиме согласования черновик выпускается в сцену и возвращается карточка, в автопилоте черновик и исправления — одним шагом Undo), «Аудит текущей сцены» (все проверщики, включая инсоляцию, на снимке живой сцены; ИИ-комментарии Нормоконтроля и Координатора — после карточки и только через API/локальные модели), `ApplyDecisionAsync` (вариант моделируется на копии текущей сцены и выпускается одним шагом Undo; изменилась сцена после планирования — позиция того же автора пересчитывается), `InterpretReplyAsync` (C#-разбор «вариант 1, но балки двутавровые стальные» → `CouncilModifiers`, иначе — модель Координатора). Настройки — `AppSettings.Council` (`Enabled`, `ConsultUser`, `Bindings`, `AiCommentaryInAudit`).

## 6. C#-солвер (`ParametricSolverService`, `StructuralAuditor`)
- **Параметрика:** `RepeatLevels` разворачивается в этажи с шагом `LevelHeight`, закруткой `TwistAnglePerFloor` и сужением `TaperScalePerFloor` вокруг оси башни; ядро `core` становится сквозным, `diagrid` остаётся параметрической оболочкой.
- **Гравитация (`ApplyGravity`):** стены и колонны этажа L садятся на перекрытие этажа L−1 (этаж 0 — на фундамент/землю), плиты — на верхний срез стен, кровли и купола — на верхнее перекрытие, бассейны утапливаются в землю. `StructuralAuditor` помечает элементы без опоры (`HasPhysicsError`, красный контур во вьюпорте) и пишет замечания в отчёт.
- **Узлы стен:** `JoinWallCorners` замыкает L- и T-узлы перпендикулярных стен при зазоре < 0.5 м.
- **Булевы вырезы проёмов:** `AttachOpenings` примагничивает окна и двери к своей или ближайшей стене (ось проёма = ось стены, толщина = стена + 0.06 м) и прописывает `HostElementId`; геометрия (`ElementGeometryBuilder.BuildWall`) режет стену на участки вокруг проёмов, IFC-экспорт создаёт `IfcOpeningElement`.
- **Авто-размещение на генплане:** `FindFreeSiteOffset` ищет свободное место вокруг существующих построек (справа, слева, спереди, сзади) с отступом 4 м без пересечения габаритов и выбирает ближайшее к центру участка; группы с совпадающими именами переименовываются.

## 8. Двусторонний обмен, Section Box и листы ГОСТ
- **Импорт DXF (`CadDxfImporterService`):** ASCII DXF (UTF-8 или ANSI-1251), `$INSUNITS`, слои, блоки `INSERT`, `LINE / LWPOLYLINE (bulge) / POLYLINE / CIRCLE / ARC / TEXT / MTEXT / 3DFACE`. Без `$INSUNITS` габарит ≥ 1000 ед. — миллиметры (×0.001); точность 0.1 мм; чужой чертёж центрируется (сдвиг кратен 1 мм), свой — нет. Контуры: полилинии, окружности, последовательные цепочки отрезков, затем циклы графа. **Режим А** (`LiftTo3D`): категории слоёв RU/EN (`Classify`) + эвристики (окружность / прямоугольник 200..1000 мм — колонна, спаренные параллельные линии 100..600 мм — стена, длинные линии с кружками/марками — оси); высоты, профили (труба, двутавр, круг — по 3D-граням) и отметки — по `3DFACE`, этажи — по низу несущих. **Режим Б** (`CreateFromContour`): клик по подложке во вьюпорте → пилюля быстрого создания; парная линия стены ищется только на слоях стен/неизвестных.
- **Окно верификации плоского DXF (`Views/DxfLiftDialog`, стеклянный `ContentDialog` на `IslandBrush`):** перед автоподъёмом чертежа без `3DFACE` (`LiftUnderlayAsync`, «В 3D» и «Открыть → DXF сразу в 3D») `CadDxfImporterService.AnalyzeLift` показывает распознанное (стены из контуров и пар линий с толщиной, колонны с типичным сечением, балки, плиты, проёмы, оси), пользователь подтверждает отметку и высоту этажа, высоту стен, толщины плиты/фундамента/покрытия, сечения колонн (по чертежу или W × D, круг — Ø W) и балок (B по чертежу или задано, H), окна (высота, подоконник) и двери; ошибки диапазонов блокируют «Построить 3D». Параметры — init-свойства `DxfLiftOptions` (у 3D-чертежа — только запасные). Обработчик окна — `MainViewModel.DxfLiftVerifier` (задаёт `MainWindow`), отмена пишет сообщение в чат.
- **Импорт IFC (`CadIfcImporterService`):** собственный STEP-парсер (IFC2X3/IFC4), единицы (`.MILLI.`, футы), цепочки `IfcLocalPlacement`, `IfcMappedItem`, `IfcBooleanClippingResult`, профили rectangle/circle/ellipse/hollow/I/arbitrary, Brep — по габариту. Окна/двери — в системе стены-хоста через `IfcRelFillsElement`; незаполненный `IfcOpeningElement` → `wall_opening` / `slab_opening` с `HostElementId`. Id элемента — из `Tag`/`AIA_Parameters` (собственный экспорт открывается без потерь). «+ К участку» ставит модель на свободное место.
- **Section Box (`SectionBoxClipper`):** отсечение треугольников 6 плоскостями (Сазерленд — Ходжмен), заливка среза материалом `MaterialKind.SectionCut` по ориентированным отрезкам сечения (ненулевая обмотка); модели отсечённых элементов — в мировых координатах (единичная матрица), `_geometryById` хранит исходную геометрию (выделение, «Показать всё»). Перестройка по сдвигу грани — не чаще одного раза за кадр UI. «Камера по разрезу» — ортогональный вид по нормали активной грани с отметками СПДС и осями.
- **Альбом чертежей (`GostDrawingPdfExporter.ExportAlbum`, «Выпуск альбома чертежей (3 листа PDF)»):** лист 1 — план этажа фильтра с осями и размерными цепочками (1:100 на А3, если помещается, иначе А2; поле чертежа без таблиц), лист 2 — разрез по активному Section Box с высотными отметками уровней, лист 3 (А3) — «Спецификация элементов этажа» (марки плана + балки, плиты и отверстия перекрытия этажа), «Ведомость расхода стали на элемент» и «Ведомость листов альбома». Первый лист — основная надпись формы 3 («Лист N / Листов 3»), последующие — форма 2а (185 × 15). Нумерация марок общая на всех листах (`MarkRegistry`). ## 10. Тактильное моделирование (Shapr3D): Push/Pull, OSnap, мультивыделение, массивы, прогулка, инсоляция

Цели: выделенные окна/витражи, окна выделенных стен, иначе все видимые окна; расчёт в фоне (`CheckInsolationAsync`), итог — в панель, чат и InfoBar.
- **Инсоляция (`SolarShadowService`):** по региону проекта (по умолчанию Москва 55.76° / 37.62° / UTC+3), склонение по сезону (лето +23.44°, равноденствие 0°, зима −23.44°), истинное солнечное время; север плана — −Z, восток — +X. Ключевой свет — вдоль луча, цвет — от золотистого (`Warmth` при высоте < 30°) до дневного; ниже горизонта — тусклый синеватый, без теней. Тени: вершины призм элементов (с повторами этажей, закруткой, наклоном) проецируются на `Y = 0.004`, силуэт — выпуклая оболочка каждой выпуклой части плана (невыпуклый `Polygon2D` плит/кровель — `Geometry2D.ConvexPieces`: отсечение ушей + слияние Хертеля — Мельхорна; у балок, ферм и диагрида — оболочка контура), объединение — полосовая развёртка `UnionTrapezoids` (перекрытия не затемняются дважды), цвет `#40000000` (светлая тема) / `#55000000` (тёмные). В тёмных темах под тенями — матовая плоскость участка на 20 % светлее фона с вырезами чаш бассейнов. Перестройка — не чаще раза за кадр UI (`QueueShadowRebuild`); силуэты и объединение считаются в пуле по снимку видимых элементов, меш — в UI-потоке, прежние тени остаются до готовности новых (`_shadowRunning/_shadowRerun`, во время рендера 4K результат откладывается). Против z-fighting («зерна» тени и пунктира сетки сквозь плоскость участка на дальних дистанциях): теневой меш — `DepthBias = -120`, `SlopeScaledDepthBias = -1.5`; плоскость участка — только `DepthBias = -12` (больший сдвиг у непрозрачной плоскости перекрывает биллборды марок осей у земли).

## 11. Инженерная верификация и исправления Совета КБ (`Services/Verification`)
- **Плагины `IBimDesignVerifier`** (Id, Title, Order, `Verify(VerificationContext)`): обнаруживаются `BimVerificationPipeline.CreateDefault()` отражением (класс с конструктором без параметров), внешние — `Register`. Контекст — клоны элементов, постройки, оси, нагрузки, регион; экспресс-расчёт и коллизии считаются один раз (ленивые). Сбой плагина — замечание `…-FAIL`, конвейер продолжает; одинаковые замечания (код + элементы) объединяются; каждому замечанию добавляется «Оставить как есть».
- **`VerificationFinding`:** `Severity` (Info/Warning/Critical), `Code`, `Category`, `Title`, `DetailedExplanation`, `AffectedElementIds`, `Location`/`Extent` (фокус камеры), `Utilization`, `ProposedFixOptions` (`ProposedFixOption`: автор `FixAuthor` Structural/Architect/Automatic/Keep, `Priority`, `PreservesArchitecture`, `PredictedUtilization` — прогноз K_исп по моделированию на копии сцены, список `FixAction`).
- **Плагины:** `StructuralCapacityVerifier` (KE: K_исп > 1.0 без продавливания; варианты подбираются моделированием до K ≤ 0.95 — утолщение плиты шагом 10 мм (КБ), балки по осям колонн h ≥ L/12 + доводка толщины (Конструктор), промежуточные колонны в центрах пролётов, сквозные до фундамента (Архитектор), сечение колонн/балок), `SpanToDepthRatioVerifier` (SPAN: балка h ≥ L/15, сталь L/20; плита h ≥ L/30; консоль h ≥ L/10; ж/б колонна l0/h ≤ 25, сталь λ ≤ 120; плита на < 3 опорах), `VerticalLoadPathVerifier` (VLP: опора в пустоту, на тонкую (< 250 мм) или неармированную консоль без балки, колонна над пролётом плиты; варианты — стойка до фундамента или ригель под стеной, перенос на ось нижней колонны, удаление дубля), `StairAndOpeningAccessVerifier` (ACCESS: проём над маршем, высота в свету 2.0 м, ширина марша 0.9 м, двери 0.8 × 1.9 м, привязка проёмов к стене, проём вне стены), `SeismicAndStabilityVerifier` (SEIS: ядро/диафрагмы при ≥ 9 эт. или > 28 м — по 2 ж/б стены ≥ 3 м в каждом направлении на нижнем этаже, эксцентриситет центра жёсткости ≤ 15 % плана, перегрузка узлов продавливания > 1.0), `MemberIntersectionVerifier` (XSECT: балка сквозь окно/дверь/проём — опустить верх проёма или уменьшить высоту балки с проверкой K_исп, проём врезается в перекрытие, частично наложенные колонны), `ClashVerifier` (CLASH: отверстие плиты по каркасу, проём на колонне — сдвиг или сужение у колонны, дубликаты), `SolverAuditVerifier` (AUDIT: StructuralAuditor на копии), `InsolationVerifier` (SUN: СанПиН, только при `IncludeInsolation`, до 40 окон).
- **`DesignFixEngine`:** действия `FixActionKind` применяются по Id без записи Undo (порядок: удаления и проёмы → опоры → плиты/балки/колонны → сечения → проёмы плит → жёсткость); `Sandbox` — независимая копия сцены для моделирования; `AddColumnStack` — стойка вниз через все перекрытия до вертикальной опоры, фундамента или земли; утолщение плиты сохраняет низ, несущий слой пирога принимает прирост, отверстия режут новую толщину. Топология каркаса — `StructuralTopology` (опоры плиты, точка наибольшего пролёта, запретные зоны лестниц/проёмов, сетка колонн, отпечаток сцены `Fingerprint`).
- **`CouncilPlanner`:** глобальные варианты карточки — позиция Конструктора, позиция Архитектора, «исправить всё автоматически на усмотрение КБ» (одинаковые наборы объединяются); каждый моделируется на песочнице (K_исп, коллизии, критичные после, бетон, новые элементы). `ApplyVariant` применяет выбор и стабилизирует модель до трёх проходов (остаточные критичные замечания и коллизии/проёмы — автоматическими вариантами), уточнения ГИПа (`CouncilModifiers`: профиль/материал балок и колонн, минимальная толщина плиты, размеры) переписывают действия.
## 12. Архитектурная подача: 3D-рулетка, White Clay, рендер 4K
- **3D-рулетка (`Services/MeasurementService`, `Views/Viewport3DControl.Measure.cs`, клавиша `M` / кнопка «Рулетка (M)», `MainViewModel.IsMeasureMode`):** клики ставят P1/P2 вместо выбора элементов (ViewCube и служебные модели — игнор). Точка — хит-тест поверхности элемента (`FindHits`, пустоты пропускаются), иначе горизонтальная плоскость через P1 или земля; OSnap (без Alt): углы и середины рёбер габарита элемента под курсором в радиусе 12 px экрана (`SnapKind.Vertex`), затем `SmartSnapService.SnapPoint` на отметке точки (бейдж и пунктир — общий `ShowSnap`). Живая акцентная линия с засечками 45° (`MeasurementService.Strokes`: выступ за засечки, засечки в плоскости, обращённой к камере; размеры — `StrokeSizes` по длине и масштабу экрана), маркеры точек. Капсула (`MeasureCanvas`, стеклянный `IslandStyle`): «L = 5 000 мм», ΔX/ΔY/ΔZ, «Наклон 53,13°» (при ΔY ≠ 0); после второго клика — «Закрепить размер на чертеже» / «Новый замер», у выбранного закреплённого размера — «Удалить размер» (Delete тоже). Esc: сброс замера, повторно — выход. Пилюля сверху: подсказка шага и «Размеров: N».
- **`PinnedDimensions` (`SceneStateService.Dimensions.cs`, модель `PinnedDimension`: Id, Start/End [x,y,z] м, Label):** в снимке Undo/Redo (закрепление и удаление — по шагу Undo), событие `DimensionsChanged`; `LoadScene(…, dimensions)` — null сохраняет текущие (при `clearHistory` — очищает), новая сцена (пресет, ИИ «Новое», импорт IFC/DXF) передаёт `[]`. Во вьюпорте — `TopMostGroup3D` поверх модели (графит в светлой теме и макете, текст темы — в тёмных), подпись — билборд значения в мм; засечки перестраиваются после поворота камеры. Экспорт: DXF — слой `DIMENSIONS` (раздел 7), листы ГОСТ — `GostDrawingRequest.Dimensions`: на плане/схеме каркаса — размеры этажа (по высоте пересекают интервал этажа), на разрезе — все, в проекции вида (значение = длина проекции, < 50 мм не выводятся), тонкая линия с выступом 2 мм, засечки 45° основной линией, текст над линией; `GostDrawingResult/GostAlbumResult.PinnedDimensions`.
- **Белый макет (`IsClayMode`, кнопка «Макет»):** `ArchitecturalMaterials.GetClay` — все материалы матовый гипс `#F4F4F6` (стекло и вода — полупрозрачный гипс, срез — `#C7C7CC`, пустоты — служебные), рёбра `#2C2C2E` толщиной 1.15 поверх заливки (каркас принудительно Solid); свет и падающие тени — по Солнцу региона и времени (`MainViewModel.IsSunLighting = IsSolarEnabled || IsClayMode`), карта напряжений перекрывает макет.
- **Рендер 4K (`Viewport3DControl.RenderHighResolutionAsync`, Экспорт → «Снимок экрана 4K (PNG)»):** `RenderHost.Resize(3840, 2160)` → `RenderToBitmapStream` → PNG (`BitmapEncoder`), затем возврат размера. Скрываются Gizmo/ручки/выделение, привязки, живой обмер, Section Box, подсветка коллизий, ViewCube и индикатор осей; толщина линий масштабируется под кадр. SwapChainPanel — flip-модель: захват возвращает предыдущий кадр, поэтому перед каждым захватом то же состояние рисуется дважды (`InvalidateRender` + `UpdateAndRender`). Прозрачный фон — разностная альфа по кадрам на чёрном и белом фоне (`ExtractAlpha`: тени и стёкла полупрозрачны), без сетки и плоскости участка; на время рендера (`_highResRendering`) перестройка теней откладывается.

## 13. Модули: ведомость объёмов и 3D-армирование

- **Параметрические инструменты (`ParametricToolsService`, `MainViewModel.ParametricTools.cs`, карточки «Параметрические инструменты» в конце инспектора):** «П-образная лестница» (без выделения — в центре постройки активного этажа, при выбранном марше — «Заменить на П-образную» на его месте): `PlanUShaped` — подступенков `round(высота этажа / 150 мм)`, марши поровну (нечётный — первому), проступь 300 мм, ширина марша 900…3000 мм, зазор 200 мм; `BuildUShapedStair` — марш 1 вдоль локальной +Z, площадка (`terrace` 200 мм, не `slab` — не сбивает `LevelElevations`, заходит на 50 мм под второй марш как опору) на половине высоты, марш 2 повёрнут на 180°; число ступеней марша — `ArchitecturalElement.StepCount` (0 — по высоте, ~170 мм; геометрия `BuildStairs`); в перекрытиях постройки над клеткой вырезается `slab_opening` (отверстия плиты над лестницей объединяются); один шаг Undo, новые элементы выделяются. «Скатная кровля по углу» (выбрана кровля или плита): высота конька = tg α · пролёт / 2 (пролёт — короткая сторона, конёк вдоль длинной; 5…60°, по умолчанию 25°); кровля меняет форму на месте (низ сохраняется, отверстия и пирог плоского покрытия снимаются), над плитой создаётся новая кровля `metal_roof` по её контуру.
- **3D-армирование (`Rendering/RebarCageBuilder`, `Views/Viewport3DControl.Rebar.cs`, `MainViewModel.IsRebarView/RebarInfoText`):** схема по `LocalBounds` геометрии элемента (поворот и сдвиг — `ElementGeometry.Transform`): колонна — стержни по контуру (шаг ≤ 200 мм, круглая — по окружности) и хомуты 15d (100…300 мм), балка — каркас вдоль длинной оси, хомуты 200 мм, прямоугольные плита/фундамент/терраса/плоская кровля — сетки 200 × 200 (верхняя при h ≥ 120 мм или у фундамента); защитный слой 40 мм; диаметры — `ReinforcementCalculator.Compute` по K_исп. Стены/ядра, полигональные и повторяемые плиты, трубы и двутавры не схематизируются. Линии — `TopMostGroup3D` («рентген»), без выделения — каркасы колонн и балок (≤ 600), с выделением — выделенное; пилюля с составом армирования под пилюлей выделения. Перестройка — не чаще раза за кадр (`QueueRebarRebuild`), во время рендера 4K скрыто.
